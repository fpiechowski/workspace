# D6 build-from-scratch building blocks — round 1

**Summary.** Every layer a from-scratch build needs has a maintained, recently released off-the-shelf part (all released within the last 2 weeks as of 2026-10-12, except node-pty and xterm.js). Session control: Claude Agent SDK 0.3.296 and OpenCode 1.19.0 / 2.x SDK. Unifying protocol: ACP schema v1.25.0 with TS SDK 1.8.0. Exposing app state: MCP TS SDK v2 (2.3.1). Terminal: node-pty 1.1.0 + xterm.js 6.0.0. Shell: Electron 44 or Tauri 2.12. Git worktrees: no library offers a real worktree API, so the app has to shell out to `git`.

The biggest non-technical constraint is Anthropic's credential policy. Third-party apps may not offer claude.ai login or route Agent SDK requests through Pro/Max credentials; developers "should use API key authentication". An end user may still sign in to the **unmodified Claude Code binary** with their own subscription. So a subscription-funded solo app has two options: drive the `claude` CLI (PTY or headless) under the user's own login, or accept API-key billing for Agent SDK use.

A second risk is churn. OpenCode is in the middle of a major-version transition: v1.19.0 adds `opencode upgrade --major`, and a new `@opencode/sdk`/`@opencode/client` 2.0.27 has an in-process host. ACP still needs vendor `_meta` extensions for things like subagents.

Effort evidence comes from repo histories, not retrospectives. No first-person retrospective with hours/weeks was found.
- **Crystal:** one author did ~92% of 672 commits. It went from repo creation to v0.1.0 in 7 days and was deprecated after about 9 months.
- **Emdash (YC):** 10,440 commits and 100+ contributors. Its trackers have 85 issues with "windows" and 91 with "pty" in the title.
- **Vibe Kanban:** sunset when its company shut down, for business reasons, not technical ones.

## Leads

- Nimbalyst (Crystal's successor, MIT since 2026-04-29 per implicator.ai, a secondary source): check its repo for agent-integration architecture and Windows notes.
- Emdash: read issues labelled windows/pty for concrete failure modes, and its `tooling/prototypes/cow-worktree` for copy-on-write worktrees.
- Check whether `@opencode/sdk` 2.x runs under Node/Electron or needs Bun, and whether `opencode serve` v2 adds multi-directory support (opencode.ai/v2/docs).
- Read Claude Code `/docs/en/sessions#where-the-session-picker-looks` and `/docs/en/headless` for driving the CLI path, which is clearly allowed for subscriptions.
- Anthropic `contact-sales` covers "previously approved" exceptions. A personal-use clarification could come from support.claude.com.
- ACP `session/fork` RFD status; the ACP v2 alpha changes.
